Synthesize the voice and lock the timing to the script.

Read videos/<id>/state.json first; update it last. Full spec: docs/MASTER_PLAN.pdf. Config: config/pipeline.json.

## Inputs
- videos/<id>/script.txt, brand/voice.json, brand/pronunciations.json, config/pipeline.json

## Outputs
- videos/<id>/audio/voice.wav (48 kHz)
- videos/<id>/timeline/words.json + timeline/words.frames.json + align_report.json
- studio project skeleton via make_plugin_files.py (projects/<slug> + config.json)
- beats draft for the storyboard; cache\tts\ paragraph cache

## Done when
- voice.wav rendered; align report >=95% word match; beats drafted; P3+P4 done in state.json.

## Stop and ask when
- Alignment is below 95% word match: HARD STOP - show align_report.json, do not continue to P5.
- The voice sounds wrong (clipping, bad pronunciations): fix prons/cache first, ask before re-take 3.

## How (run in order; stop on the first failure)
1. `& C:\channel\.venv\Scripts\python.exe pipeline\tts.py --video <id>`
   Kokoro per paragraph, hash-cached in cache\tts\ (editing one paragraph re-synthesizes only it),
   24 kHz output resampled to 48 kHz -> audio/voice.wav. Voice from brand/voice.json; espeak-ng ships
   via pip espeakng-loader.
2. `& C:\channel\.venv\Scripts\python.exe pipeline\make_plugin_files.py --video <id>`
   creates the studio project + config.json for this video.
3. `& C:\channel\.venv\Scripts\python.exe pipeline\align.py --video <id>`
   faster-whisper small.en int8 on CPU, script-as-truth; writes timeline/words.json in the EXACT plugin
   format {"source","words":[{word,start,end}]} + timeline/align_report.json; HARD FAIL below 95% match.
   (words.frames.json comes later, generated by make_plugin_files.py once master.json exists.)
4. `& C:\channel\.venv\Scripts\python.exe pipeline\beats.py --video <id>`
   kit beats draft - a starting point only; the storyboard owns the final master.json.
5. Preview: point the user at voice.wav (and a paragraph-level tap-through if easy).

## Gate 2 (with ch-run)
The user reviews 02_script.md and listens to audio/voice.wav together; ch-run stops there. After
"approved gate2 <id>" the narration is FROZEN: any wording/fact/voice change later reopens Gate 2 and
flushes downstream work (see ch-revise routing). Mark P3+P4 done only after approval.
